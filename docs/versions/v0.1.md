First working version, built in one evening from the idea: *look up any word in any
language, see where its roots came from and where they went, laid out radially
around the word.*

## What v0.1 does

- **Search** any word in any script. Exact match first, then diacritic-insensitive,
  then prefix (FTS5). Results grouped with language and gloss.
- **Radial map** with the looked-up word in the centre:
  - above — *came from* (inherited / borrowed / derived / calque / root edges)
  - below — *went on to* (words whose etymology points back at this one, plus
    Wiktionary's Descendants trees)
  - left — cognates
  - right — kin: affix parts, words formed from it, doublets
  - outer ring — cousins: other words that share one of its immediate ancestors
- Click any word to make it the centre. URLs are stable: `/w/<lang>/<word>`.
- Side panel: every Wiktionary entry for the word (part of speech, glosses,
  full etymology text), full relation lists, link to Wiktionary.
- "Surprise me" picks a well-connected word from a hub language.
- Light/dark themes, phone layout, no JS dependencies (vanilla + SVG).

## Architecture

```
kaikki.org  --(weekly, curl -z)-->  loki:/opt/gloss/data/raw-wiktextract-data.jsonl.gz
                                      │  gloss.ingest  (pigz | orjson | sqlite)
                                      ▼
                                    loki:/opt/gloss/build/gloss.sqlite
                                      │  rsync + atomic mv   (deploy/refresh.sh, cron Sun 05:00)
                                      ▼
                                    zephyr:/opt/gloss/data/gloss.sqlite   (read-only, reopened on inode change)
                                      │  gloss.service: uvicorn 127.0.0.1:8902
                                      ▼
                                    Apache vhost gloss.nthmost.com  (Let's Encrypt)
```

Two hosts because zephyr (3 GB RAM, 2 cores) can't build the DB but can serve it.

### Data model (`gloss/ingest.py`)

| table | contents |
|---|---|
| `entry` | one row per Wiktionary entry: lang, word, pos, etymology number, first 3 glosses, etymology text, romanization |
| `word` | one row per (lang, word): folded key, gloss, n_entries; FTS5 external-content index on `word`/`folded` |
| `edge` | `src` (the later word) ← `dst` (origin), `rel`, `via` (`etym` or `desc`), gloss and romanization from the template |
| `lang` | code → name, harvested from entries, descendants nodes, and template expansions (voted) |
| `meta` | built_at, source, counts |

Relations: `inh`, `bor`, `der`, `calque`, `root`, `cog`, `noncog`, `affix`, `doublet`.

Edge sources, per entry:
1. `etymology_templates` — inh/bor/der/lbor/calque/root, cog/noncog, af/suffix/prefix/compound…,
   doublet, and the compact `{{ety|lang|:inh|lang:word|:bor|…}}` chains (walked as a chain).
2. `descendants` — the nested tree; each node becomes `node ← parent`, `bor` if tagged borrowed else `inh`;
   grouping nodes without a word ("Italo-Romance") are skipped and their children attach upward.

Junk filtering: language codes validated against `^[a-z][a-z0-9]{1,3}(-[a-z0-9]{1,8}){0,3}$`,
legacy `LL.`/`ML.`/`VL.` aliases mapped, wiki-markup fragments dropped.

### Name resolution (`gloss/norm.py`, `app.resolve`)

Wiktionary links point at entry names that strip some marks the display form carries.
Resolution order, within one language:
1. exact
2. exact with/without the reconstruction asterisk (templates write `*ǵʰel-`, entries are `ǵʰel-`)
3. rows sharing the fully folded key (NFKD, strip combining marks, casefold) — but only
   accepted if the **light fold** (strip macron, breve, Cyrillic stress, asterisk) also matches.
   Otherwise the node is shown as *unknown* with the template's own gloss.
   This stops `*ǵʰel-` "flourish" from being matched to `*gʰel-` "call".

Etymology-only codes (`la-lat`, `la-med`, `grc-koi` …) — recognised as `base-xxx` codes with
zero entries — resolve to and centre on their base language, and edges written against any
code in that family are gathered together.

### Frontend (`static/app.js`)

Layout: two ellipses (direct relations, cousins). Each sector is filled by even angular
spacing; label boxes are measured with canvas `measureText`, and if any collide the list
is shortened from the tail and a "+n more" node is added (click → scrolls the side panel
to the full list). On narrow screens every label hangs above/below its dot.

## Deploy

- `deploy/deploy.sh` — idempotent: Gandi DNS A record (`.secrets/gandi-apikey`), git pull on
  zephyr, venv, systemd unit, Apache vhosts, certbot webroot on first run.
- `deploy/refresh.sh` — the loki cron. Does **not** git pull; update loki's clone by hand.
- Ops stub with host paths: `nthmost-systems/gloss/README.md`.

## Known limitations / ideas for v0.2

- Translations (`translations` field) are not ingested — a "same meaning elsewhere" ring
  would be cheap to add.
- Only one hop is shown; no "walk up to the root and fan out" view yet.
- Affix hubs (`un-`, `-ly`) have 10k+ formations; capped at 400 rows, 60 drawn.
- Reconstruction pages: only 1,802 Proto-Indo-European entries present in this dump; several
  well-known roots (e.g. `*ǵʰel-`) are referenced by etymologies but have no entry row.
- `cog` edges are stored once, from the citing entry's side; cousins are computed via
  shared ancestors only (depth 1).
- Language names for a handful of rare codes fall back to the code itself.
- Old French / Middle English forms cited in templates are often missing entries, so they
  render as unknown nodes (correctly, but greyer than one would like).
- No tests yet.

## Decisions worth remembering

- **kaikki over raw XML dumps.** Parsing wikitext etymology templates ourselves was never
  on the table; wiktextract already does it and publishes weekly.
- **SQLite, one file, shipped whole.** Simpler than Postgres replication; a 4 GB rsync a week is fine.
- **Build on loki, serve on zephyr.** RAM.
- **No per-language entry-name rules.** The two-level fold covers Latin/Greek/Cyrillic/Old
  English without maintaining Wiktionary's Lua logic; where it can't be sure, say "unknown".
- **Vanilla JS.** The radial layout is ~200 lines; D3 would have added more than it saved.
